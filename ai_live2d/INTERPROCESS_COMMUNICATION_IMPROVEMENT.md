# 进程间通信中断机制改进说明

## 概述
改进了桌宠应用的中断功能，使用进程间通信替代直接终止Python进程，实现更优雅和安全的中断方式。

## 主要改进

### 1. 进程间通信架构
- **双重通信机制**: Socket通信 + 文件信号备份
- **端口监听**: main.py在8889端口监听中断信号
- **信号类型**: 支持interrupt（中断）和shutdown（关闭）两种信号
- **编码兼容**: 使用UTF-8编码确保跨平台兼容性

### 2. main.py 改进
#### 新增功能
- **中断监听器**: 启动独立的监听线程处理中断信号
- **Socket服务器**: 监听本地8889端口接收UI中断命令
- **文件监控**: 定期检查中断信号文件
- **优雅中断**: 通过内部API中断TTS、ASR、LLM等服务

#### 核心方法
```python
def start_interrupt_listener(self):
    """启动中断监听器"""
    # 启动socket监听和文件监控

def _interrupt_listener_thread(self):
    """中断监听器线程"""
    # 处理socket连接和文件信号

def _perform_interrupt(self):
    """执行中断操作"""
    # 中断TTS、ASR、LLM等服务
```

### 3. UI.py 改进
#### 通信优先级
1. **首选Socket通信**: 尝试连接main.py的8889端口
2. **备用文件信号**: Socket失败时创建中断信号文件
3. **仅终止非Python进程**: 避免误杀桌宠和UI进程

#### 改进逻辑
```python

# 优先使用socket，其次使用文件信号
# 只终止非Python的音频进程
```

## 安全性改进

### 1. 进程保护
- ✅ 不直接终止Python进程
- ✅ 保护桌宠进程不被误杀
- ✅ 保护UI进程稳定运行

### 2. 通信安全
- ✅ 本地socket通信，不暴露外部端口
- ✅ 信号数据验证和异常处理
- ✅ 超时机制防止通信阻塞

### 3. 错误处理
- ✅ Socket通信失败自动回退到文件信号
- ✅ 完善的异常捕获和日志记录
- ✅ 通信超时保护

## 使用流程

### 正常中断流程
1. 用户点击UI中断按钮
2. UI尝试通过Socket发送中断信号
3. main.py接收信号并执行内部中断操作
4. 中断TTS、ASR、LLM等服务
5. UI只终止非Python的音频进程

### 备用中断流程
1. Socket通信失败
2. UI创建中断信号文件
3. main.py检测到文件信号
4. 执行相同的内部中断操作

## 配置说明

### 默认配置
- **中断端口**: 8889 (可修改)
- **信号文件**: interrupt_signal.tmp
- **通信超时**: 2秒
- **编码格式**: UTF-8

### 自定义配置
如需修改端口或其他参数，请在PetService类中调整：
```python
self.interrupt_port = 8889  # 修改端口
self.interrupt_signal_file = Path("custom_signal.tmp")  # 修改信号文件
```

## 注意事项

1. **端口占用**: 确保8889端口未被其他应用占用
2. **防火墙**: 本地通信通常不受防火墙影响
3. **文件权限**: 确保程序有创建/删除信号文件的权限
4. **编码兼容**: 在中文系统上使用UTF-8编码确保兼容性

## 故障排除

### Socket通信失败
- 检查8889端口是否被占用
- 确认main.py已正常启动
- 查看防火墙设置

### 文件信号失败
- 检查程序运行目录的写入权限
- 确认interrupt_signal.tmp文件能正常创建/删除

### 中断无效
- 检查main.py的日志输出
- 确认TTS/LLM服务正在运行
- 查看是否有异常错误信息
