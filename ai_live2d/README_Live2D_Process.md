# Live2D预览进程分离功能

## 概述

为了提高应用程序的稳定性和性能，我们将Live2D预览功能分离到独立的进程中运行。这样可以避免Live2D的OpenGL上下文和资源占用影响主UI进程的稳定性。

## 架构优势

### ✅ 优势
- **进程隔离**: Live2D预览在独立进程中运行，不会影响主UI
- **资源隔离**: OpenGL上下文和Live2D资源与主进程完全隔离
- **稳定性提升**: Live2D崩溃不会导致主应用程序崩溃
- **内存管理**: 更好的内存管理和垃圾回收
- **性能优化**: 主UI响应更加流畅

### 🔧 实现方式
- 使用 `subprocess` 模块启动独立的Python进程
- 通过命令行参数传递模型路径
- 进程间通信通过标准输入输出（可扩展为更复杂的IPC）
- 主进程监控子进程状态并处理异常情况

## 使用方法

### 1. 启动Live2D预览

在主UI中点击"预览Live2D"按钮，系统会：
1. 检查Live2D预览进程脚本是否存在
2. 验证模型文件路径
3. 启动独立的Live2D预览进程
4. 显示成功启动的消息

### 2. 进程管理

- **启动**: 自动在后台启动，无需用户干预
- **监控**: 主进程持续监控Live2D预览进程状态
- **清理**: 应用程序退出时自动清理所有Live2D预览进程
- **错误处理**: 进程异常退出时显示错误信息

### 3. 手动测试

```bash
# 使用自动检测的模型进行测试
python test_live2d_process_separation.py

# 使用指定模型进行测试
python test_live2d_process_separation.py --model-path /path/to/model.model3.json
```

## 技术细节

### 进程启动参数

```python
cmd = [
    sys.executable,                    # Python解释器路径
    'live2d_preview_process.py',      # 预览进程脚本
    '--model-path',                   # 模型路径参数
    model_path,                       # 实际模型文件路径
    '--debug'                         # 可选的调试参数
]
```

### 进程通信

目前使用简单的命令行参数传递信息，将来可以扩展为：
- 标准输入输出流通信
- 共享内存
- 网络套接字
- 命名管道

### 资源清理

应用程序退出时执行以下清理步骤：
1. 终止所有Live2D预览进程
2. 等待进程正常退出（最多3秒）
3. 强制结束未响应的进程
4. 清理进程引用

## 配置选项

### 调试模式

在 `config.json` 中启用调试模式：

```json
{
  "debug": {
    "live2d_preview": true
  }
}
```

启用后会添加 `--debug` 参数到Live2D预览进程。

### 进程监控

主进程会监控以下状态：
- 进程启动成功
- 进程运行状态
- 进程异常退出
- 进程输出信息

## 故障排除

### 常见问题

1. **进程启动失败**
   - 检查 `live2d_preview_process.py` 文件是否存在
   - 确认Python环境和依赖正确安装
   - 查看控制台错误信息

2. **模型加载失败**
   - 验证模型文件路径正确
   - 检查模型文件权限
   - 确认Live2D库正确安装

3. **OpenGL相关错误**
   - 确保系统支持OpenGL
   - 检查显卡驱动是否最新
   - 在虚拟机中可能需要额外配置

### 日志查看
